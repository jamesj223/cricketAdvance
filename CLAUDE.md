# Cricket Advance — notes for Claude

A GBA cricket game (C++20, Butano, devkitARM). Twin goals: **learn GBA homebrew dev**
and build an arcade cricket game to play on handhelds (Anbernic RG SP, Miyoo Mini Plus).

Start here: `docs/plan.md` (phases + current status / next up), `docs/design.md`
(design decisions and playtest notes), `docs/learnings.md` (per-phase lessons).

## Build
```sh
export DEVKITPRO=/opt/devkitpro DEVKITARM=/opt/devkitpro/devkitARM PATH=/opt/devkitpro/tools/bin:$PATH
make -j8
open -a mGBA cricketAdvance.gba
```
Placeholder graphics are generated by `python3 tools/make_placeholder_graphics.py`
(`--preview` writes `build/preview.png`).

## Working agreements
- **Learning matters as much as the game.** Explain the "why" (hardware constraints,
  fixed point, etc.). At the end of each phase: write that phase's section of
  `docs/learnings.md` with hands-on exercises, save the ROM as `roms/phase-N.gba`, and
  **don't start the next phase until the user says so.**
- **Playtest-driven.** Rapid prototyping, then iterate on the user's feedback. Record
  playtest verdicts and ideas in `docs/design.md`, and status in `docs/plan.md`.
- **No screen capture.** The user tests by hand (mGBA and real hardware) and reports
  back. Verify logic offline where possible (Python mirrors of the maths, preview images).
- **Commit only when asked**; the user usually pushes themselves.

## Code gotchas
- `bn::fixed` `*` and `/` are lossy — use `ca::mul` / `ca::div` (`include/ca_world.h`)
  for all physics and camera maths.
- `bn::random::get_fixed(a, a)` asserts on an empty range — use the `plus_minus` helper.
- Sprite text averages ~6 px per character; on-screen strings must fit in 240 px.
- Lower sprite z order draws on top (see `include/ca_draw_order.h`).
- Coordinates: world x, −x = off side for a right-hander; z down the pitch; h height.
  Up on the D-pad = back foot, Down = front foot (the batter faces the camera).
